# CLI 命令使用统计

## Context

CLI 的统计适用范围由 [CLI 模板](../templates/cli/AGENTS.md) 持有，本文件只定义实现方法与验收。维护者依据真实使用情况评估读取、执行和诊断入口。

## Problem

只有实现清单，无法判断哪些命令有真实消费者。后台轮询、人工调用和 agent 调用混在一起，也会误导删减判断。

## Forces

- 需要识别零调用、低频和重复入口。
- 参数可能包含消息正文、身份标识或凭证。
- 调用来源有时无法可靠识别。
- 统计不能改变命令的输出、退出码或业务行为。
- 单命令和小型 CLI 应复用同一轻量机制，不按命令数量另建统计系统。

## Pattern

在 CLI 执行入口记录本地调用日志，提供按需运行的 `usage` 命令。复用命令注册清单，补齐零调用项。统计至少包括调用次数、活跃天数、最后使用时间和退出结果。

只记录已声明的命令名、时间、耗时和退出码。不记录参数值、消息正文或凭证。明确标记调用来源；证据不足时使用 `unknown`。后台任务单独计数，已有运行日志时复用日志。

命令组与子命令分别展示。命令组包含子命令时，说明汇总口径并提供实际调用总数。明确观察窗口、开始记录时间和缺失记录的条件。

先采用本地追加日志和汇总函数。只有实际规模或消费者需求支持时，再引入数据库、采集服务或 dashboard。统计失败不影响原命令。

调用统计用于选择审查对象。删除命令前，核对真实消费者、恢复用途和维护成本。低频或零调用不能单独证明过度设计。

## Failure Modes

- 只统计出现过的命令，漏掉零调用项。
- 混合后台轮询与人工使用，误判命令价值。
- 将命令组与子命令相加，重复计数。
- 根据终端或调用频率猜测来源。
- 记录完整参数，泄露消息正文或凭证。
- 将退出码成功当作业务验收成功。
- 未说明记录覆盖范围，误把缺失记录当作未使用。
- 为统计增加独立服务或平行命令路由，扩大维护成本。

## Implementation Checklist

1. 绑定现有命令分发和注册清单。
2. 在执行入口记录允许的字段。
3. 隔离统计写入失败。
4. 提供含零调用项的 `usage` 汇总。
5. 标明来源、时间范围和汇总口径。
6. 复用并单列已有后台运行记录。

## Verification

- 通过真实 CLI 调用核对日志和汇总。
- 核对参数正文未进入日志。
- 核对失败退出码和原输出保持一致。
- 核对零调用项、命令组和后台计数。
- 模拟日志不可写，核对原命令仍正常执行。
- 核对来源未知、启用前历史和未完成调用的展示限制。
