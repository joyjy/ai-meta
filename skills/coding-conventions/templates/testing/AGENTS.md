# 测试策略约定

本模板统一处理验证、新增和减法。项目明确要求的检查继续执行。测试术语使用 fixture、stub、mock，不另造译名。

## 任务场景

| 场景 | 重点 |
| --- | --- |
| 验证当前改动 | 先复用已有检查。不足时用实际运行或临时探针补证，不默认新增永久测试。 |
| 实现或修复 | 修复先复现。判断新增检测能力是否值得持续维护，优先扩展最低有效层的已有用例。 |
| 维护或评审测试 | 对已有测试使用同一价值门槛，优先整例删除低价值覆盖，再缩小保留测试的准备数据。 |

三种场景使用下面同一流程。场景决定检查重点，不产生额外 workflow。

## 永久测试的保留标准

新增和保留都须说明具体故障后果、已有覆盖的缺口，并归入以下依据之一：

- **最小主路径验证**：必要的 smoke 或简短自检。缺少 smoke/golden 入口本身不构成新增理由，已有有效覆盖不重建。
- **真实事故回归**：已复现、有证据且需要持续防回归的缺陷。
- **具体高风险边界**：错误对象或 source revision、写入授权与资源归属、数据完整性。还包括事务与竞争写入、不可逆副作用、重大静默失败、未知结果及取消/失败恢复。
- **明确外部契约**：维护者要求持续覆盖，且有真实消费者与要求来源。agent 为本次实现自定的断言不算项目要求。

测试已存在、已通过、能检测独立场景，或实现存在分支、状态机、接口，均不足以自动保留全部组合。普通只读投影、字段搬运、文案/格式和展示与排序组合，默认不逐例保留。配置字段快照、私有 helper、标准库行为和推测兼容也使用这个默认值。例外须满足上述价值门槛。

测试基础设施自测须同时满足 2 个条件。错误可能静默造成假绿、污染真实环境或触发高风险副作用。实现包含非平凡状态、补偿或契约判断。只会让测试显式失败的问题，默认通过运行真实用例验证。

## 统一流程

1. **加载约束并绑定风险**：读取最近的项目测试说明。读取测试目录规则和必需检查。明确改动主路径、最大真实风险及已有独立验证依据。修复先用已有测试、实际命令或临时探针复现。
2. **决定检测能力**：按保留标准选择复用、新增、保留或删除。新增只补缺失的有效检测，不逐分支扩成矩阵。临时探针不自动进入永久套件。删除说明失去的检测能力、可接受风险及保留的高风险边界。有其他覆盖则给出位置，无替代测试也可以。
3. **选择最低有效层**。用单元测试验证明确的逻辑风险。集成/端到端验证真实 workflow、跨边界契约和副作用。每个命令族保留必要的最小 smoke，高风险写操作至少有一个有效集成主路径。只有能发现不同高风险故障才增加层级，不在 domain、handler、CLI 重测同一行为。使用最小 fixture 和已有工具。本地集成优先稳定环境，静态 build + serve 足够时不追求热更新。
4. **执行最小变更**。修改前检查重复覆盖。检查过时场景和实现细节耦合。优先删除整例及闲置 import/helper，再缩小保留的 fixture。不要把旧用例打包成大 case、引入通用 fixture 框架，或只换层而保留全部成本。断言验证实际行为，不以薄转发或 mock wiring 代替。多余 stub 直接删除，不用全局 lenient 掩盖。文件删除和外部动作遵守当前授权，普通测试取舍不逐项询问。
5. **验证并结束**。运行受影响检查和项目必需检查。主路径及最大真实风险已有证据后停止。仅在有新改动、失败或未解决风险时扩大验证。报告实际净减代码、进程成本、检测能力损失和未验证项。测试通过不等于覆盖没有损失。

测试数量、覆盖率和测试/代码比只用于观察。不设通用目标或下降门槛。不因数值下降补回低价值测试。真实外部义务和项目明确要求单独取证。
