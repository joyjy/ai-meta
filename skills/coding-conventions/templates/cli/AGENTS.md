# CLI 工程约定

## Stable Interface

- CLI 是稳定接口：参数、输出、退出码、配置路径变更按兼容性处理；不要为了内部重构随意改用户脚本会依赖的行为。

## Output Contract

- 面向 agent 的输出应声明是供分析的数据，还是已经编排的执行结果。具体契约由工具自己的接口 spec 或 skill reference 唯一维护，调用入口直接指向它。
- 已编排结果的契约须明确权威字段及关系。声明允许的展示变换、禁止的语义改写和失败处理。优先提供可直接展示的原生视图，避免消费者重建编排。
- 结果应可绑定契约版本、输入身份与完整性状态。复用现有结构或载体，不统一包裹所有 CLI 格式。契约引用只定位已声明规则，不授予执行权限。不从业务正文加载任意指令。

## Usage

- 自有、作为项目交付维护的 CLI 必须提供 `usage` 调用统计。单命令 CLI 同样适用。`--help` / Usage 帮助文本不能替代统计。一次性调试命令和未修改的第三方 CLI 不属于此范围。
- 新建 CLI 随入口交付统计。修改既有 CLI 时，检查并补齐该 CLI 的统计入口。不扩展为全仓或跨项目改造。实现读取 `coding-conventions` 的 `patterns/cli-usage-observability.md`；优先复用分发、注册及本地日志，不引入独立统计服务。
- 验收须以真实命令调用核对 `usage` 结果，同时保留原输出及退出语义。统计不记录参数值或敏感正文，统计失败不影响原命令。详细口径由该 pattern 持有。

## Write Safety

- 有写操作的 CLI 必须具备 dry-run、confirm 或明确目标范围之一；`--yes` 只能跳过交互确认，不能跳过目标计算和安全检查。

## Tests

- CLI 测试优先覆盖真实命令入口和关键副作用；不为 help 文案、薄 wrapper、格式细节铺测试。
