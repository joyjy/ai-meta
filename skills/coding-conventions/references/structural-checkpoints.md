# 阶段结构检查

代码任务允许分阶段执行，但结构判断覆盖当前完整 diff。

## 触发条件

- 每完成一个可独立验证的行为阶段，在开始下一阶段前检查结构。
- 后续实现需要复制同一数据 shape 时，先检查结构。
- 后续实现需要增加平行状态或镜像分支时，先检查结构。

## 检查与处置

- 暂停扩展，对照已确认的职责、业务条件和影响范围。
- 用实际消费者或读回证据验证，不能只凭功能或测试通过结束检查。
- 检查职责漂移、重复实现、平行状态和兼容路径膨胀。
- 发现实质结构风险时，按风险路由 `review-router` 的 quality 或 prune。
- 没有实质 finding 时，自动继续。
- scope 内保持行为不变的简化，先完成简化。
- 如果简化会改变 scope、数据模型或契约，请求用户决定。
