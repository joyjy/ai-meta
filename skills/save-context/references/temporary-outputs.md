# save-context: temporary outputs

仅当本轮或选中 route 存在 agent 自建临时输出时读取。

## 保留判断

- 盘点本轮创建与选中 route `Critical Context` 已登记的临时输出。展开明确引用的保留清单，不扫描无关目录。每次保存都重新判断，旧登记不构成继续保留的理由。
- 每个保留文件须对应具体的未完成动作、阻塞核验或尚需交付的验收证据。记录 exact path、purpose 和 cleanup condition。仅有“可能追溯”或“文件仍存在”不足以保留。
- 按文件用途设置可核验的清理条件。例如，新终态证据替代旧检查点，诊断已写入事实源，或文档已有可恢复版本。独立用途分别判断，不把整批文件绑定到“两 MR 全部收尾后”。
- 同一来源与验收范围已有可用的新证据时，清理失去恢复用途的旧快照、预检、轮询和重复输出。保留未解决失败的必要原始证据。禁止仅凭文件名、时间或新流水线成功认定替代成立。
- 对验收或待收尾事项，只保留恢复所需的证据。若保留文件仍引用待删原件，先确认依赖已解除或更新恢复指针。若其他 route 仍需复用同一文件，保留文件。用途、来源或依赖无法确认时，保留并记录具体缺口。

## 清理与登记

- 用 `lstat` 检查临时产物。只有 `ENOENT` 表示缺失。权限错误、挂载不可用和悬空软链不视为缺失。缺失本身不触发健康检查。
- 确认缺失时，从选中 route 及明确引用的保留清单移除登记，无需再次确认。写入前复核缺失与源内容。保留其他 route 和非登记内容。
- 用户调用 `save-context` 时，按全局删除边界清理本轮可证明自建的临时文件。已登记的旧文件须同时证明 agent 自建且 cleanup condition 已满足。满足窄例外时直接按 exact path 清理，无需再次确认。worktree、他人文件、持久 artifact 和来源不明路径仍需独立授权。禁止为绕过权限临时放宽旧条件。
- 仅为 admission/context I/O 创建的一次性 payload 不登记。收到 receipt 后按 exact path 清理。
- 删除后同步移除 context、保留清单及恢复指针中的失效登记。删除失败时保留登记，记录原因。仍需保留的文件继续登记，后续读取原文件，不重新查询或生成。
- 完成保存前，核对保留、已清理和待授权清理的文件数量。只报告实际结果。若仍有待授权项，说明具体用途、路径及受阻原因。
