# agent-assignment

主 agent 持有需求、关键判断与验收；主线模型沿用用户或客户端配置，本 skill 不自动切换。本 skill 只决定执行分流：RS 与 internal 都先判断委派净收益，再选择执行入口。委派率不是验收指标。

## 委派准入

- 在非简单任务首次广泛扫描、修改或其他实质工具调用前，用一句过程更新明确选择 `direct`、`RS` 或 `internal`，并据此执行。
- 每个完整职责先比较 direct 与委派。委派须替代实质工作，或缩短独立工作的并行耗时。比较时计入准备、排队、交接和验收成本。满足收益门槛后，优先选择健康且可用的 RS。一个职责至多一个 worker。
- RS worker 不继承主线已加载的个人规则。只读 brief 须绑定适用规则来源和验收；写入、Git、删除或外部动作前须证明 worker 已加载规则且 Host 覆盖副作用，否则保持 RS 只读。
- 职责独立、产物可验收只是必要条件。主线已有充分证据时，直接判断。禁止只为复述既有结论或生成同义摘要启动 worker。
- 能靠必要事实与精确来源独立完成时，只交接目标、权限、产物和验收；确需完整主线上下文则 direct，并说明依赖。
- RS 与 internal 都须通过同一收益门槛。派发后只能等待时，须仍能替代实质工作且只需抽样验收。主线仍须重做大部分取证时，选择 direct。
- 短问答、确定性命令、单点小改和无法交接的职责用 direct；确定性工作优先脚本或 CLI。选择 direct 时，简述收益判断或具体交接障碍。RS 健康不单独构成派工理由。
- 若平台 gate 是“除非用户或适用的 AGENTS / skill 明确要求，否则不得主动委派”，本 skill 只对满足上述准入的非简单职责提供委派授权；仍遵守平台的并行与工具可用性边界。
- 出现新的独立职责，或主线准备开始下一段实质取证、审查、实现或验证时，重新应用同一准入；不得把初始 `direct` 判断沿用到新出现的可交接职责。结果仍为 `direct` 时继续主线。
- 使用能覆盖职责的最少执行者。多个独立产物且无写入冲突时才并行。主线默认汇总并验收，不额外启动汇总 worker。独立汇总涉及实质证据协调且满足收益门槛时，才单独委派。
- CI 等确定性等待不参与自由分流。用户目标要求关注 `pending/running` 的 pipeline/job 时，先绑定 exact source/revision、验收终态、等待预算和回传任务，按 `references/dispatch-execution.md` 派 RS；取得匹配的接受回执才算交接。主线不得自行轮询或等待；接入失败只对原来源做一次有界核验，保留未完成 oracle。用户明确不等待时遵从。

## 路由档位

确定性字段提取、格式转换、批量校验或规则明确的变换优先使用已有脚本、CLI 或短命令，不为分层而启动 agent。

对候选和判定标准明确的语义分类、选择、排序或适用性检查，优先按 `jev-evaluation` 使用 Jev，避免仅为这类判断启动 worker。Jev 是 direct、RS 和 internal 都可调用的工具，不是第四类 agent；取证、实现、多步推理与验收仍按本 skill 分流。Jev 返回的路由建议须经过现有准入和权限核验。

| 档位 | 适用范围 | 外部候选 | 内部委派 / 接续 |
| --- | --- | --- | --- |
| 轻量执行 | 定向取证、材料整理、小范围修复，验收容易独立核验 | DS fast | `gpt-6-luna` medium；极短、低歧义且脚本不适合时用 low；确有推理深度缺口时用 high |
| 标准工程与分析 | 范围已确定的多文件实现、技术验证、较长追踪、材料综合与审查 | 技术执行用 DS pro；广泛阅读和文字综合用 Kimi | 简单且容易抽样验收可用 `gpt-6-luna` medium；其余按同类任务已验收表现选择。`gpt-5.6-sol` medium 纳入有界修复、定向审查与固定步骤工具操作的真实对照候选；已有有效路线的固定流程可继续使用 `gpt-6-sol`。`gpt-5.6-terra` medium 保留为对照候选 |
| 疑难判断 | 未收敛的复杂根因、架构约束冲突、关键设计评审 | 不强行寻找外部等价档 | 主线先收束证据和判断缺口；`gpt-6-astra` medium 仅在用户明确决定时引入，不能把困难本身当作升级依据 |

- 不按代际、新旧或“更强”预设优先级。复杂、多步、涉及权限或运行态不直接推导为 6 Sol / 6.1 Sol / Astra 更可靠；先区分推理缺口、目标保持、授权理解和运行链路故障。只有具体推理或检查深度不足才试调 effort，不能用提高 effort 替代效果验收。
- 对照落在原本需要执行且可独立验收的真实任务，不为凑样本派工或重复生产写入。同类表现未知且存在适合的标准任务时，可抽样分给 `gpt-5.6-sol` medium；它是挑战者，不因其他模型失败就成为默认。按每轮实际 Agent/model/effort、任务类型和上下文条件核对一次验收、用户催促、主线补做、返工、耗时与用量；样本不足不做优劣或节省结论，不据少量样本淘汰候选。
- 同模型委派不视为节省 Codex 用量；独立产物须满足前述收益门槛。任务变长、测试失败或额度用满不自动触发换模型或升级。
- `internal` 显式传入目标 `model`、`reasoning_effort` 和 `fork_turns: "none"` 或正数轮次，不继承主线模型。
- 档位不可确认或不可用时重新比较 direct 与可用路线，不临时修改注册配置。
