# grill

`grill` 是探索模式的高强度连续追问，用于把 plan、设计、规则或协作模式压到相互理解足够、可执行或可放弃。它不是一次性澄清，也不是泛泛提建议。

## Core Loop

每轮必须包含：

1. 复述刚刚已经收束的结论。
2. 指出核心 plan 里下一个仍不明确、会影响方案成败或执行边界的问题。
3. 提出一个问题；这个问题必须会改变 plan 的结构、边界、状态机、数据模型、发布面、责任分配或验收方式。
4. 除非用户明确停止，或双方已经达成足够相互理解并能形成可执行方案，否则不要主动结束。

## Question Rules

- 每轮只问一个关键问题。
- 不要求下一个问题一定由上一个结论打开；优先攻击当前核心 plan 里仍未明确的最高影响点。
- 不问可从代码、文件、上下文或工具查明的问题。
- 不问只影响命名、占位符、普通文案、小格式或默认路径的问题；直接采用推荐默认并说明。
- 如果用户指出追问节奏错误，先修正 grill 规则或当前节奏，再继续。
- 如果用户说“重复 / 太多 / 烦了 / 够了 / 先这样 / stop”，立即停止追问，转为总结已定结论、未决问题和推荐下一步。

## Exit Condition

- 每个问题必须消除或拆开一个尚未解决的结构性决策。
- 当已经找不到会改变结构、边界、状态机、数据模型、发布面、责任分配或验收方式的问题时，立即停止追问，不为延续 grill 发明低影响问题。
- 停止时总结已定结论、仍未知但不阻塞执行的事项和推荐下一步。

## Output Shape

优先用紧凑中文：

```markdown
已收束：
...

下一个不明确点：
...

我的问题：
...

推荐默认：
...
```

`推荐默认` 只在存在可行默认时给出；不要把它伪装成用户已经同意的结论。

## With Docs

当用户要求“边 grill 边沉淀文档 / 规则 / ADR / glossary / draft”时：

- 仍然保持 `Core Loop` 的连续追问节奏。
- 每轮只把已收束结论写成最小可维护文本。
- 文档是讨论结果的沉淀，不是替代追问的输出。
- 入口文档只写当前有效规则；分析过程、试错和长推理放草稿或不落地。

## Anti-Patterns

- 问一个问题后主动停止。
- 把 grill 变成普通 checklist。
- 只关注风险，而忽略 plan 是否已经完整明确。
- 过早进入执行、实现或文件编辑。
- 用 slash command 或外部 `/grilling` 作为本 skill 的必要入口。
