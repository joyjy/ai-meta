# 个人本机工具管理

本约定用于持续维护的个人 CLI、hook 和宿主内工具。一次性排障脚本沿用临时产物规则。工程、项目和运行契约继续使用各自的已有规范。

## 归属与登记

先按职责选择 owner。跨 AI 客户端的共享规则、skill 与发布入口归 ai-meta。agent 运行环境的观察与控制（会话 hook 与本机广播、网络控制、桌面看板、Hammerspoon 配置）归 agent-pulse。其他领域的工具归对应项目。代码行数和仓库数量不决定归属。

小工具优先留在已有 owner 内。有独立职责或维护节奏时，再使用独立仓库。独立仓库可以共用上层 context，无需另建任务体系。

在已有项目入口或 README 中说明以下信息：

- owner、源码入口和 context。
- 安装命令、实际命令入口和依赖。
- 运行形态、配置与私有状态位置。
- 验证、加载回读和停用方法。

归属登记复用 [项目地图](../project-map.md) 和 [项目入口契约](../../../gtd/docs/architecture/project-index.md)。源码地图复用 [source map 契约](source-map-contract.md)。已有文档通过链接组合，不新建一套 manifest 或登记库。

## 安装与交付

源码和安装逻辑保存在 owner 仓库。ai-meta 自有工具使用 `install.sh` 发布入口。独立工具使用自己的安装入口，ai-meta 只登记关系。

安装不隐含启用 hook、修改网络或启动后台任务。需要激活时，使用已有配置入口并核对实际加载。自有 CLI 沿用 [CLI 工程约定](../../skills/coding-conventions/templates/cli/AGENTS.md)，复用现有输出、退出码和调用统计。

代码提交、入口安装、宿主加载和运行验收分别报告。本机软链安装不表示发行副本已更新。需要发行时走 owner 已有渠道，Git 和远端动作沿用现有授权边界。

## 运行形态

| 形态 | 管理方式 | 验收依据 |
| --- | --- | --- |
| 按需 CLI / hook | 调用方管理执行，不注册常驻任务 | 真实命令、输出、退出码及所需客户端加载 |
| 宿主内任务 | 项目声明宿主、加载入口、刷新周期和回执 | 源码版本、已加载版本及回执新鲜度 |
| 独立 daemon / periodic | 沿用已有运行面；没有运行面时使用 GTD runtime | 声明校验与运行回读 |

新增且没有运行面归属的独立后台任务，复用 [GTD runtime 契约](../../../gtd/docs/architecture/runtime-registration.md)。宿主已经负责调度时，保留该调度。GTD 当前只接管 daemon 和 periodic。项目声明宿主内任务，不冒充 GTD 已注册服务，也不为显示状态再起一个任务。

按需事件快照没有固定刷新期限。宿主内周期观察按实际周期声明新鲜度。收到广播、读到旧快照或看到进程，都不能单独证明业务健康。

## 维护与停用

变更安装入口、协议、宿主装配或运行形态时，同步对应 owner 文档。验证覆盖真实主路径和最大风险，完成后停止扩展。

停用时更新 owner 的安装入口、客户端 hook 或宿主加载配置。GTD 托管任务通过原 runtime 配置停用。私有配置、快照和备份沿用已有删除边界。
