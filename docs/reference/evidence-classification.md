# 证据分类

ai-meta 维护本规则。排障、研究、评审和交付共享同一分类。

## 使用条件

关键结论混合观察、计算、推断或假设时，使用本规则。关键结论指会改变排查方向、操作对象、权限、验收或风险判断的结论。

先区分证据类型，再选择措辞。无需给每句话贴标签。普通确定性回答直接说结论。

## 分类

| 类型 | 含义 | 表达方式 |
| --- | --- | --- |
| `KNOWN` | 直接观察到的内容 | “源码显示”“日志记录”“已确认” |
| `COMPUTED` | 根据明确输入计算的结果 | “按这些输入计算”，写出关键假设 |
| `INFERRED` | 根据证据推导的结论 | “据此推断”，写出依据和前提 |
| `COMMON` | 本轮未核验的通用知识 | “通常”，不作为当前实例的证明 |
| `FRAME` | 仅在模型、策略或契约中成立 | “在这个假设下”，说明现实尚未核验 |
| `GUESS` | 证据不足的候选解释 | “待验证”，写出缺口及区分候选的证据 |

类型不是固定的可信度排名。直接观察也有来源和范围限制。计算依赖输入，推断依赖前提。

## 判断边界

- 用户陈述可证明用户报告了什么，不能自动证明运行实例的状态。
- 源码可证明版本中的逻辑，不能自动证明线上加载了该版本。
- 日志中的调用记录不能自动证明操作成功。
- 检索未命中不能自动证明事件未发生。写明检索范围和日志覆盖。
- 计算结果保留输入及关键假设。输入尚未核验时，计算结果仍是条件结论。
- 推断写明证据和前提。缺失前提可能改变结论时，报告缺口。
- 证据不足的候选解释不能作为已完成、已修复或可发布的依据。

## 输出

使用当前业务的普通语言。仅在读者可能混淆证据类型时，使用“已确认”“推断”“待验证”。

用户要求概率时，先明确事件。区分两次生成相同与累计生成后任意两个相同。

技术限制不替代结论。先说证据能证明什么，再说尚未证明什么。

## 示例

### Token 排障

- 已确认：所查源码在绝对有效期判断成立时打印 `overtime`。
- 推断：token 创建于 1 年前。前提是线上版本、字段、配置和时钟正确。
- 待验证：SDK 是否仍使用旧 token。需要核对实际请求与缓存状态。

### 随机 key

如果 112 位随机数均匀且独立，两次生成相同的概率为 `2^-112`。长度筛选可能缩小有效空间。

累计生成 `n` 个时，任意两个相同的概率另行计算。公式适用条件和生成数量必须明确。

这类计算不能证明线上随机源及实际制品符合假设。
